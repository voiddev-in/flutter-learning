# Git Commit Guide — What to Commit, What Not, and What Each Folder Does

A quick reference for this repo (`flutter-learning`). Rule of thumb:

> **Commit what a human wrote or what Flutter needs to rebuild the project.**
> **Don't commit what a tool generates on your machine** (build output, caches, IDE settings, local paths).

## 2. Repo layout — which folder is used for what

```
flutter-learning/
├── README.md                 ✅ commit — repo overview
├── .gitignore                ✅ commit — root ignore rules
├── flutter-sessions/         ✅ commit — teaching notes / class guides (Markdown)
└── app/                      the Flutter app
    ├── lib/                  ✅ YOUR DART CODE. main.dart = app entry point
    ├── bin/                  ✅ standalone Dart scripts (practice, CLI) — not part of the app UI
    ├── test/                 ✅ unit & widget tests (flutter test)
    ├── pubspec.yaml          ✅ app name, version, dependencies, assets
    ├── pubspec.lock          ✅ exact dependency versions (commit for apps)
    ├── analysis_options.yaml ✅ lint rules
    ├── .metadata             ✅ Flutter's record of how the project was created (used by `flutter upgrade`/migrate)
    ├── .gitignore            ✅ app-level ignore rules
    ├── README.md             ✅ app readme
    │
    ├── android/              ✅ native Android project (Gradle, Kotlin, manifest, icons)
    ├── ios/                  ✅ native iOS project (Xcode, Swift, Info.plist, icons)
    ├── macos/                ✅ native macOS desktop project
    ├── windows/              ✅ native Windows desktop project (C++/CMake)
    ├── linux/                ✅ native Linux desktop project (C++/CMake)
    ├── web/                  ✅ web entry (index.html, manifest, icons)
    │
    ├── build/                ❌ compiled output (APK, IPA, web build) — regenerated by `flutter build/run`
    ├── .dart_tool/           ❌ Dart/pub cache for this project — regenerated by `flutter pub get`
    ├── .idea/  *.iml         ❌ Android Studio / IntelliJ settings — personal to your machine
    └── (generated files)     ❌ see list below
```

### Platform folders — commit the folder, but not the generated bits inside

| Folder | ✅ Commit | ❌ Don't commit (generated / machine-specific) |
|---|---|---|
| `android/` | `build.gradle.kts`, `settings.gradle.kts`, `gradle.properties`, `gradle/wrapper/gradle-wrapper.properties`, `app/src/**` (manifest, `MainActivity.kt`, `res/` icons & styles) | `local.properties` (your SDK paths), `gradlew`, `gradlew.bat`, `gradle-wrapper.jar`, `.gradle/`, `app/src/main/java/` (GeneratedPluginRegistrant), `*.jks` / `key.properties` (**signing keys — never commit**) |
| `ios/` | `Runner/` (AppDelegate, Info.plist, Assets), `Runner.xcodeproj`, `Runner.xcworkspace`, `Flutter/*.xcconfig` (Debug/Release), `RunnerTests/` | `Flutter/Generated.xcconfig`, `Flutter/ephemeral/`, `flutter_export_environment.sh`, `Runner/GeneratedPluginRegistrant.*`, `Pods/`, `xcuserdata/` |
| `macos/` | `Runner/`, `Runner.xcodeproj`, `Runner.xcworkspace`, `Flutter/*.xcconfig`, `RunnerTests/` | `Flutter/ephemeral/`, `Flutter/GeneratedPluginRegistrant.swift`, `Pods/`, `xcuserdata/` |
| `windows/` | `CMakeLists.txt`, `runner/`, `flutter/CMakeLists.txt` | `flutter/generated_plugin_registrant.*`, `flutter/generated_plugins.cmake`, `flutter/ephemeral/` |
| `linux/` | `CMakeLists.txt`, `runner/`, `flutter/CMakeLists.txt` | `flutter/generated_plugin_registrant.*`, `flutter/generated_plugins.cmake`, `flutter/ephemeral/` |
| `web/` | everything (`index.html`, `manifest.json`, `favicon.png`, `icons/`) | — |

All of the ❌ items above are already covered by `.gitignore` in this repo.

## 3. Never commit — quick checklist

- `build/`, `.dart_tool/`, `.flutter-plugins-dependencies`
- `.idea/`, `*.iml`, `.DS_Store`
- `android/local.properties` (contains your local SDK path)
- Any `Generated*` / `generated_plugin*` / `ephemeral/` file
- **Secrets:** `*.jks`, `key.properties`, `.env`, API keys, `google-services.json` / `GoogleService-Info.plist` with real keys

If you ever see one of these in `git status`, it means `.gitignore` is missing a rule — add the rule, don't commit the file.

## 4. `.gitignore` setup (already fixed)

The old root `.gitignore` had been copied from the Flutter SDK's own repo. Its `*.lock` rule was hiding `app/pubspec.lock`, which an app should commit so everyone gets the same dependency versions.

It has been replaced with a clean root `.gitignore` that covers:

| Section | Ignores |
|---|---|
| OS | `.DS_Store`, `Thumbs.db` |
| Editors / IDEs | `.idea/`, `*.iml`, `*.swp`, `.history/` |
| Dart / Flutter | `.dart_tool/`, `build/`, `coverage/`, `.flutter-plugins*`, `.pub-cache/` |
| Generated registrants | macOS / Windows / Linux `GeneratedPluginRegistrant` files |
| Logs / symbols | `*.log`, `app.*.symbols`, `app.*.map.json` |
| **Secrets** | `.env`, `*.jks`, `*.keystore`, `key.properties` |
| Exception | `!pubspec.lock` → **is** committed |

The `.gitignore` files inside `app/`, `app/android/`, `app/ios/`, and so on stay as Flutter generated them. They handle the native build files.

## 5. Day-to-day workflow

```bash
git status                 # see what changed
git add <files>            # stage only what you meant to change
git diff --staged          # review before committing
git commit -m "Add enum practice and build-modes notes"
```

Tip: avoid `git add .` blindly at the repo root — check `git status` first so nothing generated or secret sneaks in.
